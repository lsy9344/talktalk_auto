# Story 5.2: inbox_log 컬럼 정의(권장 스키마)

## Status

Done

## Story

**As a** 시스템 운영자(프로젝트 오너),
**I want** Google Sheets `inbox_log` 탭의 컬럼(순서/의미)을 코드로 고정하고, “로그 row 1줄”을 그 스키마대로 만들 수 있게 하고,
**so that** Worker가 처리 결과를 항상 같은 형태로 기록(감사 로그)할 수 있다.

## Background & Context

이 프로젝트는 고객 문의를 처리한 뒤, 결과를 **Google Sheets에 기록**해서 운영자가 나중에 확인할 수 있게 합니다.

Story 5.1에서 “로그 스프레드시트/탭”과 `GoogleSheetsClient`(append) 준비를 끝냈습니다. 이제 Story 5.2에서는 **`inbox_log`의 컬럼 스키마(권장)** 를 확정해서 코드가 그 순서대로 값을 만들 수 있게 합니다.

[Source: docs/architecture.md#lambda-worker-rag--llm-처리]

- Story 5.1이 Done 이어야 합니다. (Spreadsheet ID 설정 + `GoogleSheetsClient.append_row()` + smoke test 스크립트) [Source: docs/stories/5.1.story.md]

### AC1: `inbox_log` 컬럼 이름/순서를 PRD 8.2와 동일하게 유지한다

아래 컬럼 **이름/순서** 를 코드에서 “고정”한다.

| # | 컬럼명 | 타입 | 예시 | 설명 |
|---:|---|---|---|---|
| 1 | row_id | string | `20251219-000123` | 내부 식별자(시간+증가값) |
| 2 | created_at_kst | datetime | `2025-12-19 14:22:11` | 기록 시각 |
| 3 | channel_id | string | `wc******` | 채널 식별 |
| 4 | channel_name | string | `A스토어` | 사람이 알아보기 위한 이름 |
| 5 | user_id | string | `al-...` | 톡톡 사용자 식별값(변하지 않는 값) |
| 6 | event | string | `send` | 이벤트명 |
| 7 | aggregation_id | string | `2025-12-24T10:30:00Z` | 메시지 조합 세션 id(첫 메시지 시각). 단일 메시지는 `-` |
| 8 | message_count | number | `3` | 이번 질문에 모인 메시지 수. 단일 메시지는 `1` |
| 9 | question_raw | string | `교환 어떻게 해요?` | 고객 원문(조합 시 `\\n` 연결, 500자 제한 - 넘으면 뒤에서 500자만) |
| 10 | question_masked | string | `교환 어떻게 해요?` | 로그/텔레그램용 마스킹 버전(조합/500자 제한 동일) |
| 11 | kb_used | string | `doc123:c_04;doc999:c_02` | 사용한 chunk 요약(내부용) |
| 12 | draft_answer | string | `안녕하세요 ...` | LLM 답변 초안 |
| 13 | confidence | number | `0.86` | 0~1 |
| 14 | risk_level | string | `LOW` | LOW/MEDIUM/HIGH |
| 15 | send_to_user | boolean | `FALSE` | 자동 발송 여부(결과) |
| 16 | global_mode | string | `TEST` | TEST/PROD |
| 17 | channel_mode | string | `TEST` | TEST/PROD/DISABLED |
| 18 | action_taken | string | `NOT_SENT` | NOT_SENT/SENT/FAILED |
| 19 | talktalk_send_result | string | `-` | PROD일 때 API 응답(성공/코드) |
| 20 | telegram_alert_sent | boolean | `TRUE` | 알림 여부 |
| 21 | telegram_reason | string | `KB 부족` | 알림 사유 |
| 22 | latency_ms_total | number | `8421` | 처리 총 시간(메시지 조합 대기 포함) |
| 23 | error_summary | string | `-` | 오류 있으면 요약 |

- 추가 규칙(예시 기준):
  - `row_id`는 예시처럼 `YYYYMMDD-######` 형태를 따른다. (KST 날짜 + 증가값)  
  - `created_at_kst`는 예시처럼 `YYYY-MM-DD HH:MM:SS` 형태를 따른다. (KST)

### AC3: 질문 텍스트 규칙(조합/500자 제한)을 `question_raw`, `question_masked`에 동일 적용한다

- 메시지 조합 시: 시간순 정렬 후 `\\n`으로 연결한다.
- 500자를 넘으면 **뒤에서 500자만** 사용한다.
- 단일 메시지면:
  - `aggregation_id = "-"`,
  - `message_count = 1`

[Source: docs/prd/54-message-aggregation-30초-타임-윈도우.md]

### AC4: 테스트가 있고 통과한다

최소 아래를 테스트로 막는다:

- 컬럼 순서가 바뀌지 않는지(길이/순서)
- 500자 제한이 “뒤에서 500자” 규칙을 지키는지
- 단일/집계 케이스에서 `aggregation_id`, `message_count` 기본값이 맞는지

## Dev Notes

### Previous Story Insights

- `GoogleSheetsClient.append_row(values)`가 이미 있고, 시트 append는 재시도 2회 + Circuit Breaker 패턴을 사용합니다. [Source: docs/stories/5.1.story.md]
- Spreadsheet ID는 `GOOGLE_SHEETS_SPREADSHEET_ID` 환경 변수로 주입됩니다. [Source: docs/stories/5.1.story.md]

### Google Sheets API (요약)

- Base URL: `https://sheets.googleapis.com/v4`
- 로그 append 엔드포인트:
  - `POST /spreadsheets/{spreadsheetId}/values/{range}:append`
  - Sheet: `inbox_log`
  - Value Input Option: `USER_ENTERED`
- 실패 시 재시도 2회 + Telegram 알림이 필요합니다. (중요 데이터 손실) [Source: docs/architecture.md#google-sheets-api] [Source: docs/architecture.md#에러-처리-패턴]
