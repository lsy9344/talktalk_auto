# Story 4.2: Developer Prompt (정책/스키마 강제)

## Status

Ready for Review

## Story

**As a** 시스템 운영자(프로젝트 오너),
**I want** LLM(Developer Prompt)을 PRD 문구 그대로 코드에 고정해두고,
**so that** LLM이 반드시 정해진 JSON 스키마로만 출력하도록 강제할 수 있다.

## Background & Context

System Prompt(Story 4.1)는 “역할/톤/안전 규칙”을 고정합니다.

Developer Prompt(Story 4.2)는 “출력 형식(스키마)”을 고정합니다.

이 프로젝트의 Worker는 LLM을 호출할 때:

- System + Developer + User Prompt를 합쳐 넣고
- JSON 응답을 파싱/검증한 뒤
- `send_to_user` / `needs_operator` 등을 기준으로 “자동 발송 가능/불가”를 판단합니다.

그래서 Developer Prompt도 **PRD에 있는 문장을 한 글자도 바꾸지 않고** 코드에 넣어야 합니다.

## Acceptance Criteria

### AC1: PRD 7.2의 Developer Prompt를 “그대로” 코드에 둔다

- 아래 텍스트를 **줄바꿈 포함 그대로** 복사해 코드 상수로 둔다.
- 임의로 문장/띄어쓰기/따옴표를 바꾸지 않는다.

```text
너는 반드시 아래 JSON 스키마를 준수해서만 출력한다.
추가 텍스트/코드블록/마크다운/설명 문장을 출력하면 실패로 간주된다.

[JSON 스키마]
{
  "draft_answer": "string",
  "confidence": "number (0.0~1.0)",
  "send_to_user": "boolean",
  "needs_operator": "boolean",
  "risk_level": "string (LOW|MEDIUM|HIGH)",
  "reasons": ["string", "..."],
  "citations": [
    {
      "doc_id": "string",
      "doc_title": "string",
      "section_path": "string",
      "chunk_id": "string"
    }
  ],
  "followup_questions_for_operator": ["string", "..."],
  "suggested_quick_reply": ["string", "..."]
}

[추가 규칙]
- draft_answer는 “고객에게 보내도 되는 완성형 문장”으로 작성하되,
  send_to_user=false인 경우에도 운영자 참고용으로 최대한 도움이 되게 작성한다.
- KB 근거가 충분하지 않으면 send_to_user=false로 한다.
- citations는 실제로 참고한 KB chunk만 넣는다(없으면 빈 배열).
- risk_level HIGH인 경우는 원칙적으로 send_to_user=false.
```

[Source: docs/prd/72-developer-prompt-정책스키마-강제.md]

### AC2: Developer Prompt를 “developer role 메시지”로 만들 수 있어야 한다

- LLM 호출용 메시지에서 아래 형태로 쓸 수 있어야 한다:
  - `{"role": "developer", "content": DEVELOPER_PROMPT}`
- (주의) System Prompt는 Story 4.1에서 준비되어 있고, User Prompt는 다음 스토리에서 이어서 붙입니다. [Source: docs/prd/epic-4-llm-integration-prompt-engineering.md]

### AC3: 테스트가 있고 통과한다

최소 아래를 테스트로 막는다:

- `DEVELOPER_PROMPT` 상수가 PRD 7.2 텍스트와 정확히 같은지 (문장/줄바꿈 포함)
- “developer role 메시지” 헬퍼가 올바른 dict를 만드는지

[Source: docs/architecture/coding-standards.md#test-strategy-and-standards]
