# Story 2.4: PROD 전송(보내기 API) 구현 (TalkTalk Send API Integration)

## Status

Done

## Story

**As a** 시스템 운영자(프로젝트 오너),
**I want** PROD에서 “보내도 됨”으로 결정된 답변을 TalkTalk Send API로 고객에게 자동 전송하고,
**so that** TEST에서는 절대 발송하지 않으면서, 운영 시에는 자동 응답을 할 수 있다.

## Acceptance Criteria

1. TalkTalk Send API로 메시지를 보낼 수 있는 `TalkTalkClient`가 있다. 최소 요구:
   - Base URL: `https://gw.talk.naver.com`
   - `POST /chatbot/v1/event`
   - Headers: `Content-Type: application/json;charset=UTF-8`, `Authorization: <CHANNEL_AUTH_TOKEN>`
   - Body: `{ "event": "send", "user": "<USER_ID>", "textContent": { "text": "<ANSWER>" } }`
   [Source: docs/prd/epic-2-message-processing-pipeline.md#story-24-prod-전송보내기-api-명세] [Source: docs/prd/101-요청-형태공식-예시-기반.md] [Source: docs/architecture.md#naver-talktalk-send-api] [Source: docs/architecture/tech-stack.md]
2. Send API 호출은 **Worker(비동기 처리)에서** 하도록 설계되어 있다. (Webhook Ingest에서 동기 호출 금지) [Source: docs/prd/102-비동기-처리-원칙.md] [Source: docs/architecture.md#naver-talktalk-send-api]
3. Send API는 `make_send_decision()` 결과가 `send_to_user=true` 그리고 `action="SEND_LOG_NO_ALERT"`인 경우에만 호출된다. [Source: docs/architecture.md#decision-logic-implementation] [Source: src/functions/worker/decision.py]
4. Authorization 토큰은 하드코딩하지 않는다. 채널별 토큰을 사용할 수 있게 **ChannelConfig의 `talktalk_auth_parameter_name`**(SSM Parameter 이름/경로)을 저장하고, 실행 중에 SSM Parameter Store(SecureString)에서 읽어온다. (로컬/테스트에서는 토큰을 함수 인자로 주입 가능) [Source: docs/architecture.md#channelconfig-채널-설정] [Source: docs/architecture.md#aws-components-summary] [Source: src/layers/shared/python/talktalk_shared/clients/telegram_client.py]
   - **중요**: AWS Secrets Manager 지원은 제거되었습니다. SSM Parameter Store만 사용합니다.
5. HTTP 통신 규칙:
   - 타임아웃은 10초
   - 5xx 또는 타임아웃은 1회만 재시도한다(중복 발송 방지)
   - 4xx는 재시도하지 않는다
   - Circuit Breaker를 적용한다(연속 5회 실패 → 10분간 요청 막기, 이후 1회 성공하면 다시 정상) 
   [Source: docs/architecture.md#naver-talktalk-send-api] [Source: docs/architecture.md#에러-처리-패턴]
6. Send API 실패 시:
   - error code는 `E006`으로 처리한다
   - 시스템은 멈추지 않고(예외를 삼키거나 상위에서 처리), Telegram 알림을 보낼 수 있다
   - Telegram/로그에는 PII(민감정보)를 넣지 않는다(필요 시 마스킹)
   [Source: docs/architecture.md#에러-처리-패턴] [Source: docs/architecture.md#naver-talktalk-send-api] [Source: docs/architecture/coding-standards.md#필수-규칙-ai-에이전트-준수-필수] [Source: docs/stories/2.3.story.md]
7. 위 동작은 유닛 테스트로 검증된다(AAA, pytest). 최소 포함:
   - 성공(200 OK) 요청 형태/헤더/바디 검증
   - 4xx: 재시도 없음
   - 5xx: 1회 재시도 후 실패
   - timeout: 1회 재시도 후 실패
   [Source: docs/architecture/coding-standards.md#test-strategy-and-standards]

### API 사양(요약)

[Source: docs/architecture.md#naver-talktalk-send-api]
[Source: docs/prd/101-요청-형태공식-예시-기반.md]

- URL: `https://gw.talk.naver.com/chatbot/v1/event`
- Method: `POST`
- Headers:
  - `Content-Type: application/json;charset=UTF-8`
  - `Authorization: <CHANNEL_AUTH_TOKEN>`
- Body(JSON):
  - `event`: `"send"`
  - `user`: 톡톡 user_id
  - `textContent.text`: 고객에게 보낼 답변 텍스트

### 토큰/시크릿

[Source: docs/architecture.md#channelconfig-채널-설정]
[Source: docs/architecture.md#aws-components-summary]

- 채널 설정(ChannelConfig)에 `talktalk_auth_parameter_name`이 있습니다.
- 이 이름(경로)으로 SSM Parameter Store에서 채널별 Authorization 토큰을 읽습니다.
- 토큰 값은 로그/에러/Telegram에 절대 남기지 않습니다.
- **주의**: AWS Secrets Manager(`talktalk_auth_secret_arn`) 지원은 제거되었습니다. SSM Parameter Store만 사용합니다.

### 실패 처리(중요)

[Source: docs/architecture.md#에러-처리-패턴]
[Source: docs/architecture.md#naver-talktalk-send-api]

- Timeout: 10초
- Retry: 1회만 (5xx/timeout만)
- Circuit Breaker: 연속 5회 실패면 10분간 요청을 막는다(중복/연쇄 실패 방지)
- 실패하면 error code `E006` (TalkTalk 발송 실패)
- 실패해도 시스템은 계속 동작 (운영자 알림으로 대응)
