# Story 6.2: 메시지 포맷(Plain Text / Markdown 겸용)

## Status

Done

## Story

**As a** 시스템 운영자(프로젝트 오너),
**I want** Telegram 알림 메시지를 PRD에 있는 정해진 템플릿(A/B/C) 형태로 만들고,
**so that** 운영자가 메시지를 읽기 쉽고, 상황(불확실/오류/PROD 발송 보류)을 빠르게 구분할 수 있다.

## Background & Context

Story 6.1에서 “Telegram 알림 공통 원칙(항상 포함할 정보 + 마스킹)”을 정리했습니다. 이번 Story 6.2는 그 원칙을 **실제 메시지 텍스트 포맷**으로 고정합니다.

PRD는 아래 3가지 상황별 템플릿을 권장합니다:

- (A) 불확실/리스크로 무응답 처리
- (B) 시스템 오류(OpenAI/Sheets/Send API 실패 등)
- (C) PROD인데 정책으로 발송 막힘

각 템플릿은 “Plain Text / Markdown 겸용”을 목표로 합니다.

## Acceptance Criteria

### AC1: 템플릿 (A) “운영자 확인 필요” 메시지를 만든다

아래 템플릿(A) 형태를 만족하는 문자열을 만든다:

```text
[톡톡 알림] 운영자 확인 필요 ⚠️
- 채널: {{channel_name}} ({{channel_id}})
- 상담자ID: {{user_id}}
- 집계: {{aggregation_id}} / count={{message_count}}
- 모드: global={{global_mode}} / channel={{channel_mode}}
- 사유: {{reasons_joined}}
- 위험도: {{risk_level}} / confidence={{confidence}}

[고객 질문(마스킹)]
{{question_masked}}

[추천 답변 초안(고객에게는 아직 미전송)]
{{draft_answer}}

[운영자 체크 질문]
- {{q1}}
- {{q2}}

[시트 Row]
row_id={{row_id}}
```

[Source: docs/prd/92-메시지-포맷plain-text-markdown-겸용.md]

### AC2: 템플릿 (B) “시스템 오류” 메시지를 만든다

아래 템플릿(B) 형태를 만족하는 문자열을 만든다:

```text
[톡톡 알림] 시스템 오류 🚨
- 채널: {{channel_name}} ({{channel_id}})
- 상담자ID: {{user_id}}
- 집계: {{aggregation_id}} / count={{message_count}}
- 단계: {{stage}} (예: LLM_CALL / SHEETS_APPEND / SEND_API)
- 오류요약: {{error_summary}}

[고객 질문(마스킹)]
{{question_masked}}

[재시도]
- attempt={{attempt}} / max={{max_attempts}}
row_id={{row_id}}
```

[Source: docs/prd/92-메시지-포맷plain-text-markdown-겸용.md]

### AC3: 템플릿 (C) “PROD 발송 보류” 메시지를 만든다

아래 템플릿(C) 형태를 만족하는 문자열을 만든다:

```text
[톡톡 알림] PROD 발송 보류 ⛔
- 채널: {{channel_name}} ({{channel_id}})
- 상담자ID: {{user_id}}
- 집계: {{aggregation_id}} / count={{message_count}}
- 사유: {{reasons_joined}}
- confidence={{confidence}} / risk={{risk_level}}

질문(마스킹): {{question_masked}}
초안: {{draft_answer}}
row_id={{row_id}}
```

[Source: docs/prd/92-메시지-포맷plain-text-markdown-겸용.md]

### AC4: PII(민감정보) 마스킹을 지킨다

- Telegram 메시지에는 `question_raw`를 쓰지 않고, `question_masked`만 사용한다.
- `user_id`는 마스킹된 값으로 넣는다.
- 전화번호/이메일/카드번호 등은 그대로 남지 않도록 `mask_question()`을 적용한다.

[Source: docs/prd/91-공통-원칙.md]
[Source: docs/architecture.md#privacy-and-masking-requirements]
[Source: docs/architecture/coding-standards.md#필수-규칙-ai-에이전트-준수-필수]
[Source: src/layers/shared/python/talktalk_shared/utils/masking.py]

### AC5: 테스트가 있고 통과한다

최소 아래를 테스트로 막는다:

- (A)/(B)/(C) 템플릿에서 “필수 라인/필드”가 빠지지 않는지
- `question_masked`에 전화번호/이메일/카드번호가 그대로 남지 않는지
- `aggregation_id`/`message_count`가 단일/조합 케이스에서 올바르게 들어가는지

[Source: docs/architecture/coding-standards.md#test-strategy-and-standards]

## Dev Notes

### Previous Story Insights

- 지금 `format_alert_message()`는 PRD 9.2 템플릿과 다릅니다. 이번 Story 6.2에서는 “PRD 템플릿 그대로”로 메시지 문자열을 만들게 고칩니다. [Source: src/functions/worker/telegram_message.py] [Source: docs/prd/92-메시지-포맷plain-text-markdown-겸용.md]
- Telegram 전송은 `python-telegram-bot`를 쓰며, `parse_mode=Markdown`가 기본입니다. (그래서 텍스트가 Markdown에서도 깨지지 않게 단순한 포맷을 유지합니다) [Source: src/layers/shared/python/talktalk_shared/clients/telegram_client.py] [Source: docs/architecture.md#telegram-bot-api]

### Where each field comes from (값 출처)

- `channel_name`, `channel_id`: ChannelConfig에서 가져온다. [Source: docs/architecture/source-tree.md]
- `user_id`, `question`: webhook event에서 가져온다. (하지만 Telegram에는 마스킹해서 넣는다) [Source: docs/architecture.md#privacy-and-masking-requirements]
- `aggregation_id`, `message_count`: 집계 사용 시 AggregationState에서 가져온다. (단일 메시지는 `-` / `1`) [Source: docs/prd/82-inboxlog-컬럼-정의권장-스키마.md] [Source: docs/stories/2.5.story.md]
- `reasons`: `evaluate_alert_triggers()` 결과 리스트 [Source: docs/stories/2.3.story.md]
- `risk_level`, `confidence`, `draft_answer`: LLM 결과에서 가져온다. [Source: docs/architecture.md#core-workflows]
- `row_id`: Sheets 로그 row를 만들 때 생성된 값 [Source: docs/prd/82-inboxlog-컬럼-정의권장-스키마.md] [Source: docs/stories/5.2.story.md]
- (오류 템플릿) `stage`, `error_summary`, `attempt`, `max_attempts`: 재시도/에러 처리 로직에서 가져온다. [Source: docs/architecture.md#에러-처리-패턴]

### Testing

- 유닛 테스트는 “문자열에 필수 라인이 들어갔는지”를 확인하는 방식이 가장 단순합니다. [Source: docs/architecture/coding-standards.md#test-strategy-and-standards]
- 마스킹은 `mask_question()`로 강제하고, 테스트에서도 전화번호/이메일/카드번호가 남지 않는지 확인합니다. [Source: docs/architecture.md#privacy-and-masking-requirements] [Source: src/layers/shared/python/talktalk_shared/utils/masking.py]
