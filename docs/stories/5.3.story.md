# Story 5.3: 운영 규칙

## Status

Done

## Story

**As a** 시스템 운영자(프로젝트 오너),
**I want** Google Sheets `inbox_log`에 기록할 때 TEST/PROD 규칙(`send_to_user`, `action_taken`)과 PII 마스킹 규칙을 코드로 고정하고,
**so that** 로그/알림이 항상 같은 기준으로 남고, 민감정보가 새지 않게 한다.

## Background & Context

Story 5.1/5.2에서 아래 준비는 끝났습니다:

- Google Sheets에 로그를 남길 수 있는 `GoogleSheetsClient`가 있습니다. [Source: docs/stories/5.1.story.md]
- `inbox_log` 컬럼 스키마(23개)와 `SheetsLogRow` 모델이 있습니다. [Source: docs/stories/5.2.story.md] [Source: docs/prd/82-inboxlog-컬럼-정의권장-스키마.md]

이번 Story 5.3에서는 “운영 규칙”을 확정해서, Worker가 로그를 남길 때 아래 값들이 **항상 같은 규칙**으로 찍히게 합니다:

- TEST/PROD 모드에 따른 `send_to_user` / `action_taken` 값 [Source: docs/prd/83-운영-규칙.md] [Source: docs/architecture.md#test-vs-prod-mode-behavior]
- `question_raw`(원문)과 `question_masked`(마스킹)의 차이, 그리고 마스킹이 필요한 이유 [Source: docs/architecture.md#privacy-and-masking-requirements]

[Source: docs/prd/epic-5-google-sheets-logging-monitoring.md#story-53-운영-규칙]

## Acceptance Criteria

### AC1: TEST 모드에서는 `send_to_user=FALSE`, `action_taken=NOT_SENT`로 기록한다

- 아래 중 하나라도 TEST이면 “TEST 모드”로 본다:
  - `global_mode == TEST`
  - `channel_mode == TEST`
- TEST 모드에서는:
  - `SheetsLogRow.send_to_user == False`
  - `SheetsLogRow.action_taken == "NOT_SENT"`
  - 고객 발송(TalkTalk Send API 호출)은 하지 않는다.

[Source: docs/prd/83-운영-규칙.md]
[Source: docs/architecture.md#test-vs-prod-mode-behavior]
[Source: docs/prd/52-자동-발송sendtousertrue-허용-조건.md]

### AC2: PROD 모드에서는 발송 결과에 따라 `action_taken`을 기록한다

- PROD 모드에서 자동 발송을 **시도하지 않는 경우**:
  - 예: `make_send_decision()`이 `send_to_user=false`를 반환
  - `action_taken == "NOT_SENT"`
- PROD 모드에서 자동 발송을 **시도한 경우**:
  - 성공이면 `action_taken == "SENT"`
  - 실패이면 `action_taken == "FAILED"` 이고, Telegram 알림을 보낸다(또는 최소 시도한다)
- `talktalk_send_result`는 아래 기준을 따른다:
  - 발송을 시도하지 않았으면 `"-"`
  - 발송을 시도했으면 “성공/실패를 알 수 있는 값(예: 상태코드/에러코드/간단 사유)”을 기록한다

[Source: docs/prd/83-운영-규칙.md]
[Source: docs/architecture.md#naver-talktalk-send-api]
[Source: docs/architecture.md#test-vs-prod-mode-behavior]
[Source: docs/stories/2.2.story.md]
[Source: docs/stories/2.4.story.md]

### AC3: `question_raw` / `question_masked` 규칙을 지켜서 기록한다

- `question_raw`:
  - 고객 원문을 저장한다 (원문 저장은 허용) [Source: docs/architecture.md#데이터-보호]
  - 메시지 조합 시 `\\n`으로 연결한다. [Source: docs/prd/54-message-aggregation-30초-타임-윈도우.md]
  - 500자를 넘으면 **뒤에서 500자만** 기록한다. [Source: docs/prd/82-inboxlog-컬럼-정의권장-스키마.md]
- `question_masked`:
  - `mask_question()`로 PII(전화번호/이메일/카드번호 등)를 마스킹한다. [Source: src/layers/shared/python/talktalk_shared/utils/masking.py]
  - 조합/500자 제한 규칙은 `question_raw`와 동일하게 적용한다. [Source: docs/prd/82-inboxlog-컬럼-정의권장-스키마.md]
- Telegram/CloudWatch Logs에는 `question_raw`를 쓰지 않고, `question_masked`만 사용한다. [Source: docs/architecture.md#privacy-and-masking-requirements] [Source: docs/architecture/coding-standards.md#필수-규칙-ai-에이전트-준수-필수]

### AC4: 테스트가 있고 통과한다

최소 아래를 테스트로 막는다:

- TEST 모드일 때 `send_to_user=false`, `action_taken=NOT_SENT`가 되는지
- PROD 모드에서 발송 성공/실패 케이스에 따라 `action_taken`이 `SENT/FAILED`로 찍히는지
- `question_masked`에 PII가 그대로 남지 않는지(전화번호/이메일/카드번호)

[Source: docs/architecture/coding-standards.md#test-strategy-and-standards]

#### 아직 값이 없을 때 “기본값” 규칙(권장)

`SheetsLogRow`는 23개 컬럼을 모두 채워야 합니다. (append는 1줄 리스트 형태) [Source: docs/stories/5.2.story.md]

- `channel_name`: 채널 설정에 이름이 있으면 그 값을 쓰고, 없으면 `channel_id` 또는 `"-"`를 쓴다. [Source: src/layers/shared/python/talktalk_shared/repositories/channel_config.py]
- `aggregation_id`, `message_count`:
  - 단일 메시지면 `aggregation_id="-"`, `message_count=1` [Source: docs/prd/82-inboxlog-컬럼-정의권장-스키마.md]
  - 집계(30초 윈도우)면 집계 세션 id와 메시지 수를 기록한다 [Source: docs/stories/2.5.story.md]
- `kb_used`: 사용한 chunk가 없으면 `"-"`, 있으면 `"{doc_id}:{chunk_id}"`를 `;`로 연결 [Source: docs/prd/82-inboxlog-컬럼-정의권장-스키마.md]
- `draft_answer`: 아직 답변 초안이 없으면 `"-"`
- `confidence`: 아직 값이 없으면 `0.0`
- `risk_level`: 아직 값이 없으면 `"HIGH"` (안전 기본값, 결정 로직도 기본을 HIGH로 둠) [Source: src/functions/worker/decision.py]
- `talktalk_send_result`:
  - 발송을 시도하지 않았으면 `"-"`
  - 시도했으면 `send_answer_if_allowed()`의 결과(reason/에러코드)를 짧게 기록 [Source: src/functions/worker/send_answer.py]
- `telegram_alert_sent`, `telegram_reason`:
  - 알림을 보내지 않으면 `telegram_alert_sent=false`, `telegram_reason="-"` [Source: docs/prd/82-inboxlog-컬럼-정의권장-스키마.md]
  - 알림을 보내면 reasons를 `;`로 연결해 `telegram_reason`에 넣는다 [Source: src/functions/worker/alert_rules.py]
- `latency_ms_total`: 처리 시작~끝을 ms로 기록한다. (집계면 “첫 메시지 시각~처리 끝”으로 잡는 것을 권장) [Source: docs/prd/54-message-aggregation-30초-타임-윈도우.md]
- `error_summary`: 오류가 없으면 `"-"`, 있으면 에러 코드/짧은 요약(예: `E005: Sheets append failed`) [Source: docs/architecture.md#google-sheets-api]
