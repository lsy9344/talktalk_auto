# Story 4.3: User Prompt Template (런타임 구성)

## Status

Done

## Story

**As a** 시스템 운영자(프로젝트 오너),
**I want** LLM(User Prompt Template)을 PRD 문구 그대로 코드에 고정해두고,
**so that** Worker가 런타임 값(채널/모드/질문/KB)을 넣어서 “user role 메시지”를 만들 수 있다.

## Background & Context

System Prompt(Story 4.1)는 “역할/톤/안전 규칙”을 고정합니다.

Developer Prompt(Story 4.2)는 “출력 스키마(JSON)”를 고정합니다.

User Prompt(Story 4.3)는 매 요청마다 바뀌는 정보를 넣는 자리입니다:

- 채널 정보 (channel_id, channel_name)
- 운영 모드 (global_mode, channel_mode)
- 고객 메시지 (user_id, question_raw)
- (있으면) 추가 컨텍스트 (inflow, referer, from)
- RAG로 찾은 KB 청크들 (kb_chunks)

Worker는 LLM 호출 시 Prompt를 `System + Developer + User`로 구성해야 합니다. 그래서 User Prompt 템플릿도 **PRD 문장을 한 글자도 바꾸지 않고** 코드에 넣어야 합니다.

[Source: docs/prd/73-user-prompt-template-런타임-구성.md]

## Acceptance Criteria

### AC1: PRD 7.3의 User Prompt Template을 “그대로” 코드에 둔다

- 아래 텍스트를 **줄바꿈 포함 그대로** 복사해 코드 상수로 둔다.
- 임의로 문장/띄어쓰기/기호를 바꾸지 않는다.

```text
[채널 정보]
- channel_id: {{channel_id}}
- channel_name: {{channel_name}}

[운영 모드]
- global_mode: {{global_mode}}   (TEST|PROD)
- channel_mode: {{channel_mode}} (TEST|PROD|DISABLED)

[고객 메시지]
- user_id: {{user_id}}
- message: {{question_raw}}

[추가 컨텍스트(있으면 제공)]
- inflow: {{inflow}}
- referer: {{referer}}
- from: {{from}}

[지식베이스(KB) - 발췌]
아래 KB 내용만 근거로 사용해 답변 초안을 작성하라.
KB에 없는 정보는 단정하지 말고, 운영자 확인이 필요하면 send_to_user=false로 하라.

{{kb_chunks}}
```

[Source: docs/prd/73-user-prompt-template-런타임-구성.md]

### AC2: 템플릿에 런타임 값을 넣어서 “user role 메시지”로 만들 수 있어야 한다

- 아래 형태의 메시지를 만들 수 있어야 한다:
  - `{"role": "user", "content": "<치환된 User Prompt 텍스트>"}`
- (주의) `{{...}}` 변수들은 런타임 값으로 채운다.
- (주의) `inflow/referer/from`는 “있으면 제공”이므로, 값이 없을 때도 안전하게 동작해야 한다(예: 빈 문자열로 처리).

[Source: docs/prd/73-user-prompt-template-런타임-구성.md]

### AC3: 테스트가 있고 통과한다

최소 아래를 테스트로 막는다:

- `USER_PROMPT_TEMPLATE` 상수가 PRD 7.3 텍스트와 정확히 같은지 (문장/줄바꿈 포함)
- 템플릿 치환 함수가:
  - 모든 변수를 값으로 잘 바꾸는지
  - `{"role": "user", "content": ...}` dict 형태를 잘 만드는지
  - optional 값이 None/빈 값이어도 에러가 나지 않는지

[Source: docs/architecture/coding-standards.md#test-strategy-and-standards]
