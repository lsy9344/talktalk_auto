# Story 3.1: 문서 구조 (채널 KB + 공통 KB)

## Status

Done

## Story

**As a** 시스템 운영자(프로젝트 오너),
**I want** 채널별 KB 문서와 공통 KB 문서 목록을 정리하고 한 곳에 저장해서,
**so that** Worker/Indexer가 같은 기준으로 문서를 가져와 RAG를 안정적으로 돌릴 수 있다.

## Background & Context

RAG는 “문서(KB)에서 근거를 찾고 → 그 근거로 답변을 만드는 방식”입니다.

이 프로젝트는 문서를 2가지로 나눠서 쓰려 합니다:

- **채널 전용 KB**: 채널마다 다른 문서 (예: 채널 A 전용 안내문)
- **공통 KB**: 모든 채널에 같이 쓰는 문서 (예: 공통 정책/배송/환불)

[Source: docs/prd/epic-3-rag-knowledge-base-management.md#story-31-문서-구조]
[Source: docs/prd/61-문서-구조.md]
[Source: docs/architecture.md#lambda-worker-rag--llm-처리]

### Dependencies

- DynamoDB 테이블 `ChannelConfig`, `GlobalMode`가 이미 있어야 합니다. [Source: docs/architecture.md#dynamodb-테이블-정의-aws-sam-templateyaml]

## Acceptance Criteria

### AC1: 채널 전용 KB 문서 목록(채널 → doc_ids)

- DynamoDB `ChannelConfig` 아이템에 `doc_ids: List[String]`가 있고, 이 값이 **“이 채널이 쓰는 채널 전용 Google Docs 문서 ID 목록”**이다.
- `ChannelConfig`의 PK는 `channel_id`이다.

[Source: docs/prd/epic-3-rag-knowledge-base-management.md#story-31-문서-구조]
[Source: docs/architecture.md#channelconfig-채널-설정]

### AC2: 공통 KB 문서 목록(common_doc_ids)

- 공통 KB 문서 ID 목록(`common_doc_ids: List[String]`)이 **한 곳**에 저장되어 있고, 모든 채널이 공유한다.
- 저장 위치는 DynamoDB `GlobalMode` 테이블(전역 설정 테이블)에 **추가 아이템**으로 저장한다:
  - PK: `config_key = "COMMON_DOC_IDS"`
  - Attributes: `doc_ids: List[String]`
- 공통 KB 문서 목록이 없으면(아이템이 없으면) 안전하게 `[]`로 처리한다.

[Source: docs/prd/epic-3-rag-knowledge-base-management.md#story-31-문서-구조]
[Source: docs/architecture.md#globalmode-전역-모드]

### AC3: 채널별 “최종 문서 목록” 계산 규칙

아래 규칙으로 채널별 최종 문서 목록을 만든다:

1. 기본은 `ChannelConfig.doc_ids` (채널 전용)
2. `ChannelConfig.common_doc_enabled == true`이면 `common_doc_ids`도 추가한다
3. 최종 결과는 **중복 doc_id가 없어야** 한다 (같은 doc_id가 여러 번 들어가면 1번만 남김)
4. 순서는 “채널 전용 doc_ids 먼저, 공통 doc_ids는 뒤”를 유지한다

[Source: docs/architecture.md#channelconfig-채널-설정]
[Source: docs/architecture.md#lambda-worker-rag--llm-처리]

### AC4: 테스트

아래 테스트가 작성되어 통과한다:

- `common_doc_enabled=true/false`에 따라 최종 문서 목록이 달라지는지
- 중복 doc_id가 제거되는지
- (가능하면) “공통 문서 목록이 비어있을 때”도 안전하게 동작하는지

[Source: docs/architecture/coding-standards.md#test-strategy-and-standards]

### Data Models

#### ChannelConfig (채널 설정)

- `doc_ids`: 이 채널 전용 Google Docs 문서 ID 목록
- `common_doc_enabled`: 공통 KB 사용 여부 (기본 true)

[Source: docs/architecture.md#channelconfig-채널-설정]

#### GlobalMode (전역 설정)

- 공통 KB 문서 목록은 `GlobalMode` 테이블에 저장합니다.
  - PK: `config_key="COMMON_DOC_IDS"`
  - Attributes: `doc_ids: List[String]` (아이템이 없으면 `[]`로 처리)
- 코드에서 변수명은 `common_doc_ids`로 써도 되지만, DynamoDB 속성 이름은 `doc_ids`입니다.

[Source: docs/architecture.md#globalmode-전역-모드]

#### VectorIndexMetadata (벡터 인덱스 메타데이터)

- `doc_type`: `"CHANNEL_SPECIFIC"` 또는 `"COMMON"` (채널 전용/공통 구분)

[Source: docs/architecture.md#vectorindexmetadata-벡터-인덱스-메타데이터]

### Components

#### Indexer (문서 동기화)

- 문서 목록을 만들 때 `ChannelConfig`에서 `doc_ids`를 모아서 씁니다.
- 공통 문서도 결국 “문서 ID 목록” 형태로 Indexer가 알 수 있어야 합니다. (이 Story에서 “공통 문서 목록 저장”을 먼저 준비합니다.)

[Source: docs/architecture.md#lambda-indexer-문서-동기화]

#### Worker (RAG + LLM)

- RAG 검색은 “채널 KB + 공통 KB”를 같이 씁니다. 그래서 채널별 최종 문서 목록(AC3)이 중요합니다.

[Source: docs/architecture.md#lambda-worker-rag--llm-처리]
