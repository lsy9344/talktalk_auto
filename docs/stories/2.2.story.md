# Story 2.2: 자동 발송(send_to_user=true) 허용 조건 (Send Allow Rules)

## Status

Done

## Story

**As a** 시스템 운영자(프로젝트 오너),
**I want** “자동 발송을 해도 되는 조건”을 코드로 한 번 더 안전하게 막아두고,
**so that** PROD에서도 실수로 고객에게 잘못 보내는 일을 최대한 줄일 수 있다.

## Acceptance Criteria

1. 자동 발송(`send_to_user=true`)은 아래 “기본 3게이트 조건”을 **모두** 만족할 때만 가능하다: [Source: docs/prd/52-자동-발송sendtousertrue-허용-조건.md] [Source: docs/architecture.md#test-vs-prod-mode-behavior]
   - GlobalMode = `PROD`
   - ChannelConfig.channel_mode = `PROD`
   - `confidence >= channel_config.confidence_threshold` (기본 0.80, PROD 전환 시 0.85처럼 더 높게 시작 가능) [Source: docs/architecture.md#decision-logic-implementation]
   - `risk_level != "HIGH"`
   - LLM 결과가 `send_to_user=true` (LLM이 “보내도 됨”이라고 승인) [Source: docs/architecture.md#decision-logic-implementation]
2. `needs_operator=true`이면 무조건 자동 발송을 막는다(고객에게는 보내지 않음). [Source: docs/prd/71-system-prompt-고정.md] [Source: docs/prd/72-developer-prompt-정책스키마-강제.md]
3. PRD에는 `policy_flags`가 언급되어 있으므로, LLM 결과에 `policy_flags`(리스트)가 있고 비어있지 않으면 자동 발송을 막는다. (지금은 “금지 항목” 정의가 없어서, 안전하게 `policy_flags`가 하나라도 있으면 “금지로 간주”한다) [Source: docs/prd/52-자동-발송sendtousertrue-허용-조건.md]
4. 조건이 하나라도 실패하면 `send_to_user=false`이고, 이유(`reason`)와 행동(`action`)이 명확히 나온다. [Source: docs/architecture.md#decision-logic-implementation]
5. 위 규칙은 유닛 테스트로 검증된다(AAA 패턴, pytest). [Source: docs/architecture/coding-standards.md#test-strategy-and-standards]

### 왜 “추가 안전 조건”이 필요한가?

- 프롬프트가 잘 작성되어도, LLM 출력이 항상 완벽하다고 가정할 수는 없습니다.
- 그래서 Worker 쪽에서 “마지막 문(게이트)”을 한 번 더 두는 게 안전합니다. [Source: docs/architecture.md#test-vs-prod-mode-behavior]
