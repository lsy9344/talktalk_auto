## Status

## Story

**As a** 시스템 운영자(프로젝트 오너),
**I want** RAG가 찾은 KB 청크들을 PRD 권장 포맷으로 보기 좋게 문자열로 만들고,
**so that** LLM(User Prompt)에 KB 근거를 일관된 형태로 넣을 수 있다.

## Background & Context

Worker는 RAG로 KB 청크(chunks)를 찾은 뒤, LLM에게 “근거”로 같이 넣습니다.

이때 KB 청크를 아무렇게나 붙이면:

- LLM이 “근거 정보”와 “본문”을 헷갈릴 수 있고
- 나중에 citations(근거 표시)을 만들 때도 불리합니다.

그래서 PRD 7.4에서 **KB Chunks 권장 포맷**을 정해두었습니다.

[Source: docs/prd/74-kb-chunks-포맷권장.md]
[Source: docs/prd/epic-4-llm-integration-prompt-engineering.md#story-44-kb-chunks-포맷권장]
[Source: docs/architecture.md#lambda-worker-rag--llm-처리]

### Dependencies

- RAG가 청크 텍스트 + 메타데이터(`doc_id`, `doc_title`, `section_path`, `updated_at`, `chunk_id`)를 반환할 수 있어야 합니다. [Source: docs/stories/3.4.story.md] [Source: docs/stories/3.3.story.md]
- User Prompt Template(Story 4.3)은 `{{kb_chunks}}` 자리에 “문자열”을 넣도록 되어 있습니다. [Source: docs/stories/4.3.story.md]

## Acceptance Criteria

### AC1: PRD 7.4의 KB Chunks 포맷을 그대로 따른다

- 아래 포맷을 기준으로 “KB chunks 문자열”을 만든다.
- `<KB>` / `</KB>` 태그를 포함한다.
- 각 청크는 `[1]`, `[2]`처럼 1부터 번호를 붙인다.
- 각 청크 헤더 줄에는 아래 필드를 모두 넣는다:
  - `doc_id`, `doc_title`, `section_path`, `updated_at`, `chunk_id`

```text
<KB>
[1] doc_id={{doc_id}} | title={{doc_title}} | section={{section_path}} | updated_at={{updated_at}} | chunk_id={{chunk_id}}
{{chunk_text}}

[2] doc_id=...
...
</KB>
```

[Source: docs/prd/74-kb-chunks-포맷권장.md]

### AC2: 청크가 0개여도 안전하게 동작한다

- 청크가 없으면 아래처럼 “빈 KB 블록”을 반환한다:
  - `<KB>\n</KB>`

### AC3: 테스트가 있고 통과한다

최소 아래를 테스트로 막는다:

- 2개 청크 입력 → 출력 문자열이 “정확히” 예상 포맷과 같은지
- 0개 청크 입력 → `<KB>\n</KB>`를 반환하는지

[Source: docs/architecture/coding-standards.md#test-strategy-and-standards]
