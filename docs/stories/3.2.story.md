# Story 3.2: 수집/동기화 (변경 감지로 비용 줄이기)

## Status

Done

## Story

**As a** 시스템 운영자(프로젝트 오너),
**I want** Google Docs 기반 KB 문서를 정해진 주기로 동기화하고, 바뀐 문서만 다시 색인해서,
**so that** RAG가 항상 최신 문서로 동작하면서도 불필요한 비용(OpenAI 임베딩/API 호출)을 줄일 수 있다.

## Background & Context

이 프로젝트의 KB(지식 문서)는 Google Docs 문서를 씁니다.

하지만 문서는 매일 바뀌지 않습니다. 그래서 “문서가 바뀌었는지 먼저 확인”하고, **바뀐 문서만** 다시 처리해야 비용이 적게 듭니다.

- **변경 감지**: Google Docs의 `revisionId`(또는 `modifiedTime`)를 비교한다.
- **스킵**: revision이 같으면 그 문서는 다시 색인하지 않는다.
- **주기 실행 + 수동 실행**: 기본은 주 1회(또는 매일 변경 감지)이고, 필요하면 수동으로도 실행한다.

## Acceptance Criteria

### AC1: Indexer를 “주기 실행 + 수동 실행” 할 수 있다

- Indexer Lambda가 **주 1회** 스케줄로 실행된다. (EventBridge Scheduler)
- 필요하면 운영자가 수동으로도 Indexer를 실행할 수 있다. (예: 스크립트/수동 트리거)

[Source: docs/prd/62-수집동기화월-1회-업데이트-최적화.md]
[Source: docs/architecture.md#lambda-indexer-문서-동기화]

### AC2: Indexer가 “대상 문서(doc_id) 목록”을 만든다

- Indexer는 DynamoDB `ChannelConfig`를 전체 조회해서, 모든 채널의 `doc_ids`를 모은다.
- (선택) 채널에서 `common_doc_enabled=true`면 공통 문서(`COMMON_DOC_IDS`)도 포함한다.
- 최종 문서 목록은 **중복 doc_id가 없어야** 한다.
- `doc_ids`가 없으면(또는 타입이 이상하면) 안전하게 `[]`로 본다.
- 공통 문서 목록 아이템이 없으면 안전하게 `[]`로 본다.

[Source: docs/architecture.md#워크플로-4-주간-문서-동기화]
[Source: docs/architecture.md#channelconfig-채널-설정]
[Source: docs/architecture.md#globalmode-전역-모드]
[Source: docs/stories/3.1.story.md]

### AC3: 변경 감지(revisionId)로 “바뀐 문서만” 처리한다

- 각 `doc_id`에 대해 Google Docs API로 최신 `revisionId`(또는 `modifiedTime`)를 가져온다.
- DynamoDB `VectorIndexMetadata`에 저장된 `revision_id`와 비교한다.
  - 처음 보는 문서(메타데이터 없음)면 “변경됨”으로 보고 처리한다.
  - `revision_id`가 같으면 **해당 문서는 스킵**한다.

[Source: docs/architecture.md#google-docs-api]
[Source: docs/architecture.md#vectorindexmetadata-벡터-인덱스-메타데이터]
[Source: docs/architecture.md#lambda-indexer-문서-동기화]

### AC4: 변경된 문서는 벡터 인덱스를 만들고 저장한다

변경된 문서에 대해서 아래 흐름이 동작한다:

- 문서 텍스트를 가져온다
- 청킹(대략 400~800 tokens)한다
- OpenAI 임베딩을 만든다 (`text-embedding-3-small`)
- FAISS 인덱스를 만들고 S3에 업로드한다: `indices/{doc_id}.faiss`
- `VectorIndexMetadata`를 업데이트한다 (revision_id, last_modified_time, embedding_model, S3 위치 등)

[Source: docs/architecture.md#lambda-indexer-문서-동기화]
[Source: docs/architecture.md#워크플로-4-주간-문서-동기화]
[Source: docs/architecture.md#vectorindexmetadata-벡터-인덱스-메타데이터]
[Source: docs/architecture/tech-stack.md]

### AC5: 실패해도 전체 작업이 멈추지 않는다

- 특정 문서 1개 처리에 실패해도, 다른 문서는 계속 처리한다.
- 실패한 문서는 로그로 남기고(PII 금지), 필요하면 Telegram으로 요약 알림을 보낼 수 있다.

[Source: docs/architecture.md#lambda-indexer-문서-동기화]
[Source: docs/architecture/coding-standards.md#필수-규칙-ai-에이전트-준수-필수]

### AC6: 테스트가 있고 통과한다

최소 아래는 테스트로 검증한다:

- 변경 없는 문서는 재색인(임베딩/FAISS/S3 업로드)을 스킵한다
- 변경된 문서는 “업데이트 흐름”이 실행된다 (외부 API/DB는 모킹)

[Source: docs/architecture.md#통합-테스트]

### Data Models

#### ChannelConfig (채널 설정)

- `doc_ids`: 채널 전용 Google Docs 문서 ID 목록
- `common_doc_enabled`: 공통 KB 포함 여부

[Source: docs/architecture.md#channelconfig-채널-설정]

#### GlobalMode: COMMON_DOC_IDS (공통 문서 목록)

- PK: `config_key="COMMON_DOC_IDS"`
- `doc_ids`: 공통 KB Google Docs 문서 ID 목록

[Source: docs/architecture.md#globalmode-전역-모드]

#### VectorIndexMetadata (변경 감지/저장 위치 기록)

- PK: `doc_id`
- 주요 필드: `revision_id`, `last_modified_time`, `embedding_model`, `index_s3_bucket`, `index_s3_key` 등
- `doc_type`: `"CHANNEL_SPECIFIC"` 또는 `"COMMON"` (문서 구분 값)

[Source: docs/architecture.md#vectorindexmetadata-벡터-인덱스-메타데이터]

### Components

#### Indexer Lambda (문서 동기화)

- 입력: EventBridge Scheduler(주 1회) 또는 수동 트리거
- 출력: S3(FAISS 인덱스), DynamoDB(VectorIndexMetadata)
- 핵심: revision 비교로 “변경된 문서만” 처리
