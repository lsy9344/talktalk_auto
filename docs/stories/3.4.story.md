## Story

**As a** 시스템 운영자(프로젝트 오너),
**I want** RAG가 “채널 KB → 공통 KB” 순서로 필요한 근거만 적당한 개수로 찾아서,
**so that** 답변 품질은 유지하면서도 LLM 입력 토큰/비용을 줄일 수 있다.

## Background & Context

Worker Lambda는 고객 질문을 처리할 때, 먼저 KB(지식 문서)에서 관련 청크(chunks)를 찾아서 LLM에게 같이 넣습니다(RAG).

그런데 청크를 너무 많이 넣으면:

- LLM 입력 토큰이 늘어서 비용이 올라갑니다.
- 처리 시간이 길어질 수 있습니다.

여기서 `topK`는 “가장 비슷한 것 K개”를 뜻합니다.

그래서 **2단계 검색 + 개수 제한** 전략을 씁니다:

1) 채널 KB에서 먼저 몇 개(4~6) 찾기  
2) 부족한 부분은 공통 KB에서 몇 개(2~4) 더 찾기  
3) 최종은 6~10개 이내로 제한하기

[Source: docs/prd/64-retrieval-전략저비용충분성.md]
[Source: docs/architecture.md#lambda-worker-rag--llm-처리]

## Acceptance Criteria

### AC1: 채널 KB에서 먼저 topK=4~6으로 검색한다

- Worker는 `channel_id`로 ChannelConfig를 읽고, `doc_ids`(채널 전용 KB 문서 목록)를 만든다. [Source: docs/architecture.md#channelconfig-채널-설정]
- 채널 KB 검색은 **topK=4~6 범위**로 수행한다.
  - 기본값은 `6`으로 둔다. (범위 안이고, 예시 다이어그램도 Top-6을 사용) [Source: docs/prd/64-retrieval-전략저비용충분성.md] [Source: docs/architecture.md#워크플로-1-일반-메시지-처리-test-모드]

### AC2: 공통 KB에서 topK=2~4로 추가 검색한다

- ChannelConfig의 `common_doc_enabled=true`일 때만 공통 KB를 사용한다. [Source: docs/architecture.md#channelconfig-채널-설정]
- 공통 KB 문서 목록은 GlobalMode의 `config_key="COMMON_DOC_IDS"`에서 읽는다. [Source: docs/architecture.md#globalmode-전역-모드]
- 공통 KB 검색은 **topK=2~4 범위**로 수행한다.
  - 기본값은 `4`로 둔다. [Source: docs/prd/64-retrieval-전략저비용충분성.md]

### AC3: 결과 합쳐 6~10 chunks 이내로 제한한다

- 최종 청크 개수는 **최대 10개**를 넘지 않는다. [Source: docs/prd/64-retrieval-전략저비용충분성.md]
- (현실적인 예외) KB에 청크가 부족하면 6개 미만이 될 수 있다. 이 경우에도 안전하게 동작한다(에러 없이 “있는 만큼만” 반환). [Source: docs/architecture.md#lambda-worker-rag--llm-처리]
- 채널 KB 결과를 우선으로 하고, 부족하면 공통 KB 결과로 채운다. [Source: docs/prd/64-retrieval-전략저비용충분성.md]

### AC4: 반환하는 청크는 텍스트 + 메타데이터를 포함한다

- Worker가 최종으로 선택한 각 청크는 아래 정보를 포함한다:
  - `text` (LLM에 넣을 본문)
  - `doc_id`, `doc_title`, `section_path`, `updated_at`, `channel_id_or_common`, `chunk_id`
  - (선택) 검색 점수/거리(정렬에 쓴 값)
  [Source: docs/stories/3.3.story.md]

### AC5: 일부 문서가 깨져 있어도 전체 처리가 멈추지 않는다

- 특정 `doc_id`의 인덱스/청크 파일 로드가 실패해도 다른 문서는 계속 시도한다. [Source: docs/architecture.md#lambda-worker-rag--llm-처리]
- 로그/알림에 PII(전화번호/이메일 등)를 절대 넣지 않는다. (필요 시 masking 사용) [Source: docs/architecture/coding-standards.md#필수-규칙-ai-에이전트-준수-필수]

### AC6: 테스트가 있고 통과한다

최소 아래를 테스트로 검증한다:

- 채널 KB 결과가 topK 범위(기본 6)로 제한된다
- 공통 KB 결과가 topK 범위(기본 4)로 제한된다
- 최종 합계가 최대 10을 넘지 않는다
- 중복 청크(같은 `doc_id` + `chunk_id`)는 1개만 남는다
- 일부 문서 로드 실패가 있어도 함수가 예외 없이 끝난다

[Source: docs/architecture/coding-standards.md#test-strategy-and-standards]
