# Story 7.3: Go-Live 절차(운영 관점)

## Status

Done

## Story

**As a** 시스템 운영자(프로젝트 오너),
**I want** TEST에서 PROD로 안전하게 전환하는 순서/체크리스트/되돌리기(롤백) 방법을 문서로 정리하고,
**so that** 16개 채널을 단계적으로 PROD로 올릴 때 실수와 사고를 줄일 수 있다.

## Background & Context

Story 7.1/7.2까지는 “테스트 통과 조건”과 “PROD 전환 전 안전장치”를 코드/테스트로 고정했습니다.

Story 7.3은 실제 운영자가 **어떤 순서로** 모드를 바꾸고, 무엇을 확인하고, 문제가 생기면 어떻게 되돌릴지(롤백) **운영 절차(runbook)** 를 만드는 일입니다.

PRD가 제시하는 Go-Live 큰 흐름은 아래 6단계입니다:

1. 16개 채널 모두 `channel_mode=TEST`, `global_mode=TEST`로 시작
2. 1~2주간 Sheet 검증(초안 품질/근거 적절성/알림 빈도 확인)
3. 채널별로 문서 보강(월 1회 업데이트 플로우에 반영)
4. 일부 채널만 `channel_mode=PROD`로 올려 “부분 준비”
5. 마지막에 `global_mode=PROD` 전환
6. 초기 1~3일은 Telegram 알림을 촘촘히 모니터링하며 threshold 튜닝

## Dependencies

- TEST 모드 “필수 통과 조건”이 이미 테스트로 고정되어 있어야 합니다. (자동 발송 0건 / Sheets row 100% / 알림 누락 없음 / Ingest 즉시 ACK) [Source: docs/stories/7.1.story.md]
- PROD 전환 전 “안전장치”가 이미 테스트로 고정되어 있어야 합니다. (초기 threshold 0.85, HIGH 리스크 차단, echo 무시) [Source: docs/stories/7.2.story.md]
- 운영 절차에서 바꾸는 설정은 아래 2가지입니다:
  - GlobalMode: 전역 스위치 `TEST|PROD` (DynamoDB) [Source: docs/architecture.md#globalmode-전역-모드]
  - ChannelConfig: 채널별 `channel_mode` / `confidence_threshold` (DynamoDB) [Source: docs/architecture.md#channelconfig-채널-설정]
- 운영 중에는 Sheets 로그와 Telegram 알림이 “관찰 도구”로 필요합니다. [Source: docs/architecture.md#google-sheets-api] [Source: docs/architecture.md#telegram-alert-triggers]

### AC2: 시작 상태(TEST)와 “부분 PROD → 전체 PROD” 전환 순서가 명확하다

- “처음에는 전부 TEST”라는 원칙이 문서에 명확히 적혀 있다. [Source: docs/prd.md#12-go-live-절차운영-관점]
- “채널 일부만 PROD로 올려서 부분 준비 → 마지막에 global PROD” 순서가 문서에 명확히 적혀 있다. [Source: docs/architecture.md#mode-transition-strategy]

### AC3: 설정 변경 방법이 명확하다 (GlobalMode/ChannelConfig)

- 문서에 아래 정보가 들어있다:
  - GlobalMode는 `config_key="GLOBAL_MODE"` 한 건이며, `mode="TEST|PROD"`로 바꾼다. [Source: docs/architecture.md#testprod-mode-framework]
  - ChannelConfig는 `channel_id`를 Key로 가지며, `channel_mode="TEST|PROD|DISABLED"`를 가진다. [Source: docs/architecture.md#channelconfig-채널-설정]
  - PROD 전환 초기에는 `confidence_threshold=0.85` 같은 보수적 값으로 시작할 수 있다. [Source: docs/architecture.md#mode-transition-strategy] [Source: docs/prd/112-prod-전환-전-안전장치.md]
- (중요) 전역 스위치(GlobalMode)를 PROD로 바꾸면 영향 범위가 크다는 점이 문서에 강조되어 있다. [Source: docs/architecture.md#testprod-mode-framework]

### AC4: 모니터링(관찰)과 튜닝 방법이 문서에 있다

- 문서에 아래 내용이 들어있다:
  - 확인 대상: Sheets 로그(답변 초안/근거), Telegram 알림 빈도/내용 [Source: docs/prd.md#12-go-live-절차운영-관점]
  - 초기 1~3일은 Telegram 알림을 자주 보며 threshold를 튜닝한다. [Source: docs/prd.md#12-go-live-절차운영-관점]
  - (권장) `send_to_user=false` 비율을 관찰한다(너무 높으면 자동 발송이 거의 안 되거나, KB/프롬프트 품질 이슈 가능). [Source: docs/architecture.md#mode-transition-strategy]

### AC5: 긴급 롤백(되돌리기) 절차가 문서에 있다

- 문서에 아래 2가지를 모두 포함한다:
  - 즉시 전체 중단: `global_mode=TEST`로 되돌리기(킬 스위치) [Source: docs/architecture.md#mode-transition-strategy]
  - 특정 채널만 중단: 해당 채널 `channel_mode=TEST`로 되돌리기 [Source: docs/architecture.md#mode-transition-strategy]

### 핵심 개념(운영자가 꼭 알아야 하는 것)

- **TEST 모드(기본 안전 모드)**: 고객에게는 절대 발송하지 않고, Sheets 기록 + Telegram 알림으로 “검증”만 합니다. [Source: docs/architecture.md#testprod-mode-framework]
- **PROD 모드(자동 발송 가능 모드)**: 아래 3가지가 모두 “예”여야 자동 발송이 됩니다. [Source: docs/architecture.md#testprod-mode-framework]
  1. GlobalMode = PROD (전역 스위치)
  2. ChannelConfig.channel_mode = PROD (채널별 스위치)
  3. LLM 승인(신뢰도 threshold 통과 + HIGH 리스크 아님)

### 바꾸는 설정(무엇을 바꾸는가)

- GlobalMode (전역):
  - DynamoDB GlobalMode 테이블
  - `config_key="GLOBAL_MODE"`
  - `mode="TEST" | "PROD"`
  - 전역이라서 영향이 큼(긴급 중단 킬 스위치 역할) [Source: docs/architecture.md#testprod-mode-framework] [Source: docs/architecture.md#globalmode-전역-모드]
- ChannelConfig (채널별):
  - DynamoDB ChannelConfig 테이블
  - Key: `channel_id`
  - `channel_mode="TEST" | "PROD" | "DISABLED"`
  - `confidence_threshold`는 PROD 전환 초기에 보수적으로(예: 0.85) 시작 후 튜닝 가능 [Source: docs/architecture.md#channelconfig-채널-설정] [Source: docs/architecture.md#mode-transition-strategy]

### Go-Live 운영 절차(아키텍처 관점 보강)

- 채널별 TEST→PROD 전환 전에 확인할 “전제 조건(Prerequisites)” 예시가 아키텍처에 있습니다:
  - TEST 모드로 일정 기간 운영(예: 7일), 메시지 최소 개수, Sheets 품질 확인, 에러 로그 확인, KB 최신화 등 [Source: docs/architecture.md#mode-transition-strategy]
- “점진적 롤아웃(Gradual Rollout)”과 “긴급 롤백” 흐름도 아키텍처에 이미 있습니다:
  - 문제 발생 시 즉시 `global_mode=TEST`로 되돌리고, 원인 확인 후 다시 단계적으로 진행 [Source: docs/architecture.md#mode-transition-strategy]
