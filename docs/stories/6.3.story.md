# Story 6.3: 알림 중복 방지(권장)

## Status

Done

## Story

**As a** 시스템 운영자(프로젝트 오너),
**I want** 같은 질문에 대한 Telegram 알림이 짧은 시간(5~10분) 안에 여러 번 나가지 않게 중복을 막고,
**so that** 운영자가 알림 스팸에 묻히지 않고 중요한 케이스만 빠르게 볼 수 있다.

## Background & Context

Worker는 아래 상황에서 Telegram 알림을 보낼 수 있습니다:

- TEST 모드(항상 알림) [Source: docs/architecture.md#test-vs-prod-mode-behavior]
- 불확실/리스크 케이스(예: RAG 근거 부족, HIGH 리스크) [Source: docs/stories/2.3.story.md]
- 외부 API 실패(OpenAI/Sheets/Send API) [Source: docs/architecture.md#에러-처리-패턴]

그런데 같은 메시지가 다시 처리되거나(재시도/중복 트리거 등), 같은 질문으로 여러 번 알림이 나가면 운영자가 보기 힘들어집니다.

그래서 PRD 9.3에서 “중복 방지(권장)” 규칙을 제안합니다:

- 동일 `channel_id + user_id + 질문해시` 조합은 **5~10분 TTL**로 Telegram 중복 발송 방지
- `질문해시`는 **조합된 최종 질문(500자 제한 적용 후)** 기준으로 계산

[Source: docs/prd/93-알림-중복-방지권장.md]
[Source: docs/prd/epic-6-telegram-alerts-notifications.md#story-63-알림-중복-방지권장]

## Dependencies

- Telegram 알림 트리거/전송 흐름이 있어야 합니다. [Source: docs/stories/2.3.story.md] [Source: src/functions/worker/pipeline.py] [Source: src/layers/shared/python/talktalk_shared/clients/telegram_client.py]
- 질문 500자 제한 규칙이 있어야 합니다. [Source: src/layers/shared/python/talktalk_shared/models/sheets_log_row.py] [Source: src/layers/shared/python/talktalk_shared/utils/message_combiner.py]
- DynamoDB TTL을 쓰는 “중복 방지 테이블”이 있어야 합니다. [Source: docs/architecture.md#deduplicationrecord-중복-방지] [Source: src/layers/shared/python/talktalk_shared/repositories/deduplication.py]
- (집계 메시지의 경우) 조합된 최종 질문을 만들 수 있어야 합니다. [Source: docs/stories/2.5.story.md] [Source: src/functions/worker/aggregator.py]
- (권장) Story 6.2의 Telegram 메시지 포맷이 구현되어 있으면, 중복 방지 적용 효과를 바로 확인하기 쉽습니다. [Source: docs/stories/6.2.story.md]

## Acceptance Criteria

### AC1: 동일 `channel_id + user_id + 질문해시`는 5~10분 동안 Telegram 알림을 1번만 보낸다

- 같은 `channel_id`, 같은 `user_id`, 같은 `질문해시` 조합이 TTL 안에 다시 들어오면:
  - Telegram 알림 전송을 **스킵**한다.
  - 시스템은 멈추지 않고 계속 처리한다. (로그만 남기기)
- TTL 시간이 지나면 다시 알림을 보낼 수 있다.

[Source: docs/prd/93-알림-중복-방지권장.md]
[Source: docs/architecture.md#aws-components-summary]

### AC2: `질문해시` 계산 규칙을 지킨다

- `질문해시`는 아래 순서로 만든다:
  1) “최종 질문 텍스트”를 만든다
     - 집계 메시지면: `combine_messages()` 결과(이미 500자 제한 적용) [Source: src/layers/shared/python/talktalk_shared/utils/message_combiner.py]
     - 단일 메시지면: 원문 텍스트에 500자 제한을 적용한다 (뒤에서 500자만) [Source: src/layers/shared/python/talktalk_shared/models/sheets_log_row.py]
  2) 위 텍스트로 SHA256 해시를 만들고, 앞 16자만 사용한다 (중복 방지 키 길이 줄이기)

[Source: docs/prd/93-알림-중복-방지권장.md]
[Source: docs/stories/1.2.story.md#dev-notes---dedup중복-방지-규칙]

### AC3: DynamoDB TTL을 사용한다 (5~10분)

- TTL은 기본 10분을 사용한다. (PRD의 5~10분 범위 안)
- 저장소는 DynamoDB TTL 기반으로 자동 만료되게 한다.

[Source: docs/architecture.md#aws-components-summary]
[Source: docs/architecture.md#deduplicationrecord-중복-방지]

### AC4: 로그/알림에 PII(민감정보)를 남기지 않는다

- 중복 방지 로직의 로그에는 원문 질문/원문 user_id를 찍지 않는다.
- 필요하면 `question_hash` 같은 “해시 값”만 로그에 남긴다.

[Source: docs/architecture/coding-standards.md#필수-규칙-ai-에이전트-준수-필수]

### AC5: 테스트가 있고 통과한다

최소 아래를 테스트로 막는다:

- 첫 번째 알림은 보내고, TTL 안의 두 번째는 스킵되는지
- 같은 질문이라도 500자 제한(뒤에서 500자)이 적용되면 해시가 일관되게 나오는지
- 집계 메시지(여러 줄 `\n`)도 같은 규칙으로 해시가 만들어지는지

[Source: docs/architecture/coding-standards.md#test-strategy-and-standards]

## Dev Notes

### Previous Story Insights

- 현재 중복 방지는 “웹훅 중복 처리 방지” 용도로 `DeduplicationRepository`가 있습니다. (webhook body 전체 해시) [Source: src/layers/shared/python/talktalk_shared/repositories/deduplication.py]
- 이번 Story 6.3은 목적이 다릅니다: “Telegram 알림 스팸 방지” 입니다. 그래서 해시 기준을 “질문 텍스트(500자 제한 적용 후)”로 바꿉니다. [Source: docs/prd/93-알림-중복-방지권장.md]

### Data Models / Key Design

- 저장 키(권장): `TG#{channel_id}#{user_id}#{question_hash}`
  - `TG#` prefix는 기존 webhook dedup 키와 섞이지 않게 하기 위함입니다.
- TTL: 10분(기본) → DynamoDB TTL로 자동 만료

[Source: docs/architecture.md#deduplicationrecord-중복-방지]

### Final Question Text (500자 제한)

- 단일 메시지:
  - “질문 텍스트”에 500자 제한을 적용(뒤에서 500자만) [Source: src/layers/shared/python/talktalk_shared/models/sheets_log_row.py]
- 집계 메시지:
  - `combine_messages()` 결과를 사용(이미 500자 제한 포함) [Source: src/layers/shared/python/talktalk_shared/utils/message_combiner.py]

### Testing

- 핵심은 “중복이면 알림을 안 보낸다”를 테스트로 고정하는 것입니다.
- 추천 방식:
  - 중복 체크 함수/Repository는 “True/False”만 반환하게 만들어서 테스트하기 쉽게 한다.
  - TelegramClient는 모킹해서 실제 전송 호출이 1번만 일어나는지 확인한다.

[Source: docs/architecture/coding-standards.md#test-strategy-and-standards]
