# Story 2.3: 무응답 + Telegram 알림 트리거 (No-Reply + Telegram Alert Triggers)

## Status

Done

## Story

**As a** 시스템 운영자(프로젝트 오너),
**I want** “무응답(고객에게는 보내지 않음)”이 필요한 상황을 빠르게 찾아서 Telegram으로 운영자에게 알려주고,
**so that** 고객에게는 안전하게 무응답을 유지하면서, 운영자가 빠르게 개입(확인/수동 응답)할 수 있다.

## Acceptance Criteria

1. 운영자 개입이 필요한 상황을 판별하는 “알림 트리거 규칙”이 코드로 있다. 아래 트리거를 최소 포함한다. [Source: docs/prd/53-무응답-telegram-알림-트리거운영자-개입-필요.md] [Source: docs/prd/epic-2-message-processing-pipeline.md#story-23-무응답-telegram-알림-트리거운영자-개입-필요] [Source: docs/architecture.md#telegram-alert-triggers]
   - RAG 근거 부족(검색 결과 부실/유사도 낮음)
   - 리스크 HIGH (주문/결제/개인정보/분쟁 등)
   - 이미지/복합 메시지인데 텍스트가 없음
   - 질문이 너무 짧아서 정보가 부족함(예: `"?"`, `"ㅇㅇ"`, `"문의요"`)
   - LLM 출력 검증 실패(JSON 파싱 실패 등)
   - 외부 연동 실패(OpenAI/Sheets/Send API 오류)
2. TEST 모드에서는 **모든 메시지**가 “무응답 + Telegram 알림”으로 처리된다. [Source: docs/architecture.md#test-vs-prod-mode-behavior]
3. PROD 모드에서 자동 발송이 **막히는 경우**(예: `action="LOG_AND_ALERT"`) Telegram 알림이 간다. [Source: docs/architecture.md#decision-logic-implementation] [Source: src/functions/worker/decision.py]
4. Telegram 알림 메시지는 최소 아래 정보를 포함하고, PII(민감정보)는 절대 포함하지 않는다(마스킹 필수). [Source: docs/architecture.md#handling-uncertain-cases] [Source: docs/architecture.md#privacy-and-masking-requirements] [Source: docs/architecture/coding-standards.md#필수-규칙-ai-에이전트-준수-필수] [Source: docs/prd/epic-6-telegram-alerts-notifications.md#story-61-공통-원칙]
   - 채널 정보: `channel_name` / `channel_id`
   - 상담자 ID: `user_id` (마스킹된 값)
   - 모드: global / channel
   - 왜 알림인지: reasons(리스트)
   - 질문: `question_masked` (마스킹된 값)
5. Telegram Bot API `sendMessage`로 알림을 보낼 수 있다. Telegram 전송은 `python-telegram-bot`를 사용한다(Tech Stack 기준). `chat_id`는 환경 변수로 관리한다. Telegram 전송 실패는 **시스템을 멈추지 않고** 로그만 남긴다. [Source: docs/architecture.md#telegram-bot-api] [Source: docs/architecture/tech-stack.md]
6. 위 규칙은 유닛 테스트로 검증된다(AAA 패턴, pytest). [Source: docs/architecture/coding-standards.md#test-strategy-and-standards]

### 마스킹 규칙(짧게)

[Source: docs/architecture.md#privacy-and-masking-requirements]

- `user_id`: 앞 2글자 + 뒤 2글자만 남기고, 중간은 `*`로 가린다. (예: `abcdef123456` → `ab******56`)
- `question_masked`: 질문에 전화번호/이메일/고객 ID가 있으면 부분 마스킹한다.
- 결제정보(카드번호 등)로 보이는 값은 Telegram/로그에 **절대** 남기지 않는다(그 부분은 제거). [Source: docs/architecture.md#privacy-and-masking-requirements]
