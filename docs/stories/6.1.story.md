# Story 6.1: 공통 원칙 (Telegram 알림)

## Status

Review

## Story

**As a** 시스템 운영자(프로젝트 오너),
**I want** Telegram 알림 메시지에 “항상 들어가야 하는 정보”와 “마스킹 규칙”을 코드로 고정하고,
**so that** 운영자가 상황을 빠르게 파악하고, 민감정보(전화번호/이메일/카드번호 등)가 새지 않게 한다.

## Background & Context

이 프로젝트에서 Telegram 알림은 “운영자가 개입해야 하는 상황”을 빠르게 알려주는 역할입니다. (TEST 모드, 불확실 케이스, 외부 API 실패 등)

이번 Story 6.1은 “공통 원칙”을 코드로 고정합니다:

- Telegram에는 **마스킹된 텍스트**를 기본으로 보낸다
- Telegram 메시지에는 아래 정보를 **항상 포함**한다:
  - 채널명, `channel_id`
  - 상담자 id(`user_id`) (민감정보 취급 → 마스킹)
  - 질문(마스킹된 텍스트)
  - 추천 답변 초안(`draft_answer`)
  - 왜 알림인지(reasons)
  - (메시지 조합 사용 시) `aggregation_id` / `message_count`

## Acceptance Criteria

### AC1: Telegram 알림 메시지에 “공통 필드”가 항상 포함된다

Telegram 알림 메시지는 아래 정보를 **항상 포함**해야 합니다:

- 채널명 (`channel_name`)
- `channel_id`
- 상담자 id(`user_id`) → `mask_user_id()`로 마스킹된 값
- 질문 텍스트 → `mask_question()`로 마스킹된 값 (`question_masked`)
- 추천 답변 초안(`draft_answer`)
- 왜 알림인지(reasons)
- 메시지 조합 정보:
  - 조합을 사용한 경우: `aggregation_id`, `message_count`
  - 조합을 사용하지 않은 경우: `aggregation_id="-"`, `message_count=1` (표준 값)

[Source: docs/prd/91-공통-원칙.md]
[Source: docs/prd/82-inboxlog-컬럼-정의권장-스키마.md]

### AC2: Telegram 메시지/로그에 PII(민감정보)가 그대로 남지 않는다

- 전화번호/이메일/카드번호처럼 민감정보로 보이는 값은 Telegram 메시지에서 마스킹되어야 합니다.
- `question_raw`(원문)을 그대로 Telegram에 넣지 않습니다. (Telegram은 `question_masked`만 사용)

[Source: docs/architecture.md#privacy-and-masking-requirements]
[Source: docs/architecture/coding-standards.md#필수-규칙-ai-에이전트-준수-필수]
[Source: src/layers/shared/python/talktalk_shared/utils/masking.py]

### AC3: 테스트가 있고 통과한다

최소 아래를 테스트로 막습니다:

- Telegram 메시지에 AC1의 필드가 빠지지 않는지
- `aggregation_id`/`message_count`가 “단일/조합” 케이스에 맞게 찍히는지
- 질문에 전화번호/이메일/카드번호가 들어와도 Telegram 메시지에는 마스킹되어 나가는지

[Source: docs/architecture/coding-standards.md#test-strategy-and-standards]

### Telegram Bot API (구현에 필요한 최소 정보)
