# Risk Profile - Story 2.4 (2025-12-27)

## 전체 판단

- **리스크 수준**: 중간(Medium)
- 이유: 외부 API(TalkTalk) 호출이라 장애/지연이 있을 수 있어요. 다만 timeout/재시도/서킷브레이커로 위험을 줄였습니다.

## 주요 리스크와 확인 결과

1. **TalkTalk API 장애/지연(5xx, timeout) 위험**
   - 확인: timeout 10초 + 1회 재시도(5xx/timeout만) + Circuit Breaker(연속 5회 실패 시 10분 차단)로 연쇄 실패를 줄입니다.
   - 테스트: `test_talktalk_client.py`에서 4xx/5xx/timeout 재시도 규칙을 검증합니다.

2. **timeout 재시도 시 중복 발송 위험(아주 낮음)**
   - 상황: 서버가 이미 처리했는데 클라이언트만 timeout으로 실패로 보이면, 재시도로 중복 발송 가능성이 남습니다.
   - 권장: TalkTalk API가 지원한다면 idempotency 키(중복 방지 키) 적용을 검토합니다.

3. **설정 누락(토큰 파라미터 이름 없음/SSM 조회 실패) 위험**
   - 확인: `talktalk_auth_parameter_name`이 없거나, SSM 조회가 실패하면 발송을 하지 않고 `E006`으로 처리합니다.
   - 테스트: `test_send_answer_if_allowed.py`에 “누락/조회 실패” 케이스 테스트를 추가했습니다.

4. **PII(민감정보) 로그 노출 위험**
   - 확인: 로그에서 `user_id`는 마스킹하고, 토큰 값/고객 원문을 직접 남기지 않습니다.
