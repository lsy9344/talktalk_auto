# Risk Profile - Story 1.2 (2025-12-21)

## 전체 판단

- **리스크 수준**: 중간(Medium) → 외부 웹훅/인프라(SQS, DynamoDB) 연동이 있기 때문
- 대신 테스트가 있고, 로깅/중복/분기 처리가 잘 되어 있어 큰 리스크는 낮습니다.

## 주요 리스크와 확인 결과

1. **톡톡 타임아웃(3초/5초) 초과 위험**
   - 확인: Ingest는 최소 작업만 합니다(DDB 조회/put + SQS send) → 구조는 적합
   - 권장: 배포 후 CloudWatch로 p50/p95 지연시간을 확인

2. **중복 이벤트 재처리 위험(톡톡 재시도)**
   - 확인: DynamoDB Conditional Put + TTL로 10분 중복 방지 구현
   - 테스트: 중복이면 enqueue를 건너뛰는 테스트가 있습니다

3. **echo/open/leave 처리로 인한 루프/불필요 처리 위험**
   - 확인: `event != send`는 200 OK로 즉시 종료
   - 테스트: non-send 이벤트 무시 테스트가 있습니다

4. **PII(고객 식별자) 로그 노출 위험**
   - 발견: dedup_key 로그에 user_id가 포함될 수 있었습니다
   - 조치: QA에서 안전한 값만 로그로 남기도록 수정 완료
