## Detailed Risk Register

### PERF-001: 요청마다 S3에서 인덱스/청크를 읽음(캐시 없음)

- **Score: 2 (Low)**
- **Why it matters**: 문서 수가 늘어나면 S3 호출이 많아져서 처리 시간이 늘 수 있습니다.
- **Mitigation**:
  - doc_id 단위로 인덱스/청크를 캐시(LRU/TTL)해서 재사용하기
  - 운영에서 S3 get_object 횟수와 처리 시간을 모니터링하기
- **Testing Focus**:
  - 캐시 hit/miss 동작
  - 캐시된 데이터가 깨졌을 때의 예외 처리

### REL-001: VectorIndexMetadata의 index_s3_key 미사용

- **Score: 2 (Low)**
- **Why it matters**: 지금은 `indices/{doc_id}.faiss` 규칙이 고정이라 괜찮지만, 나중에 키 규칙이 바뀌면 Worker가 못 찾을 수 있습니다.
- **Mitigation**:
  - VectorIndexMetadataRepository로 index_s3_key를 읽어오는 옵션 추가 검토
  - (최소) key 규칙이 바뀌었을 때 빠르게 알 수 있도록 에러 로그/알림 개선
- **Testing Focus**:
  - 메타데이터 기반 key 조회 시나리오(정상/없음/깨짐)

- 운영 모니터링(권장): S3 호출 횟수, retrieval latency, OpenAI embeddings 호출 시간
