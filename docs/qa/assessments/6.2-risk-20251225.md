# Risk Profile - Story 6.2 (2025-12-25)

## 전체 판단

- **리스크 수준**: 낮음~중간(Low/Medium)
- 이유: Telegram 알림은 운영자가 바로 보는 곳이라 “메시지 포맷/마스킹”이 중요합니다. 이번 변경은 문자열 포맷(순수 함수) + 테스트가 잘 되어 있어 큰 위험은 적습니다.

## 주요 리스크와 확인 결과

1. **SEC-001: Telegram 알림으로 PII가 새는 위험**
   - 상황: 질문/사용자ID에 전화번호/이메일/카드번호 등이 섞일 수 있습니다.
   - 영향: 운영 채널에 PII가 보이면 보안 문제가 됩니다.
   - 확인/조치:
     - 템플릿 A/B/C 포맷터 내부에서 `mask_user_id()`/`mask_question()`을 다시 적용합니다(최종 방어선).
     - 유닛 테스트로 템플릿 A/B/C 모두 PII 마스킹을 확인합니다.

2. **REL-001: Telegram Markdown 포맷 깨짐(낮음)**
   - 상황: `parse_mode=Markdown`라서, 질문/초안에 특수문자(`_`, `*` 등)가 많으면 메시지 모양이 깨질 수 있습니다.
   - 영향: 읽기 어려워지거나, 일부 케이스는 Telegram이 메시지를 거절할 수 있습니다(가능성 낮음).
   - 제안(선택): Markdown escape/규칙을 정하거나, parse_mode를 바꾸고 escape 규칙을 정하세요.

3. **OPS-001: 시스템 오류 템플릿 적용 범위(낮음)**
   - 상황: 현재 worker 예시 코드에서는 Sheets 실패(E005)만 템플릿 B로 보냅니다.
   - 영향: 다른 오류 코드(E004/E006 등)도 템플릿 B로 보내고 싶다면 추가 매핑이 필요합니다.
   - 제안(선택): error_code/stage가 있을 때 템플릿 B를 쓰는 공통 분기 함수로 정리하면 확장하기 쉽습니다.
