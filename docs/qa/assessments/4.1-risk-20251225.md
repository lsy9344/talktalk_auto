## Detailed Risk Register

### DOC-001: PRD 문서마다 따옴표 표기가 달라 “그대로 복사” 기준 혼동

- **Score: 2 (Low)**
- **Why it matters**: 어떤 문서를 “원문”으로 볼지 애매해져, 나중에 프롬프트 비교/검증에서 혼란이 생길 수 있습니다.
- **Mitigation**:
  - PRD 샤드/에픽 문서/스토리의 프롬프트 표기를 한 곳으로 통일하기
  - “원문 기준 파일”을 하나로 정하고(예: PRD 샤드), 다른 문서는 링크만 두기
- **Testing Focus**:
  - 원문과 코드 상수의 텍스트(줄바꿈/따옴표 포함) 비교 테스트 유지

### REL-001: System Prompt 텍스트가 실수로 변경될 위험

- **Score: 2 (Low)**
- **Why it matters**: System Prompt는 답변 톤/안전 규칙에 영향을 주기 때문에, 작은 변경도 결과를 바꿀 수 있습니다.
- **Mitigation**:
  - `SYSTEM_PROMPT`는 상수로 두고, 변경 시 테스트가 실패하도록 유지
  - 코드 리뷰에서 “프롬프트 변경”을 별도 체크 포인트로 보기
- **Testing Focus**:
  - `SYSTEM_PROMPT`가 기대 텍스트와 1:1로 같은지 확인하는 테스트

## Risk-Based Testing Strategy

- 기본(필수): `SYSTEM_PROMPT` 정확 일치 테스트 + `build_system_message()` 구조 테스트
- 권장: “원문 기준 문서”를 하나로 통일한 뒤, 그 문서와 코드 상수를 자동으로 비교하는 테스트(선택)
