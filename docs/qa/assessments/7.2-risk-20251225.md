# Risk Profile - Story 7.2 (2025-12-25)

## 전체 판단

- **리스크 수준**: 낮음(Low)
- 이유: “PROD로 올리기 전 안전장치”를 코드 + 테스트로 고정했습니다. 전체 테스트 384개가 통과했습니다.

## 주요 리스크와 확인 결과

1. **SEC-001: 누락된 threshold 때문에 자동 발송이 쉬워지는 위험**
   - 상황: `confidence_threshold`가 없으면, 의도치 않게 기본값(0.80)으로 계산되어 자동 발송이 쉬워질 수 있습니다.
   - 확인/조치: `make_send_decision()`이 `confidence_threshold`가 **없을 때만** 0.85를 기본값으로 씁니다.
   - 테스트: `tests/unit/test_decision.py`에서 0.83은 차단, 0.86은 통과 가능, 그리고 “명시된 값은 그대로 사용”을 확인합니다.

2. **REL-001: HIGH 리스크인데도 자동 발송이 나가는 위험**
   - 확인/조치: PROD여도 `risk_level == HIGH`면 무조건 `send_to_user=false`로 차단합니다.
   - 테스트: `tests/unit/test_decision.py`, `tests/unit/test_alert_rules.py`에서 HIGH 리스크 차단 + 알림 이유 포함을 확인합니다.

3. **OPS-001: echo 이벤트로 무한 루프가 생기는 위험**
   - 확인/조치: Ingest는 `event != send`면 200 OK로 끝내고 SQS enqueue를 하지 않습니다. (echo 포함)
   - 테스트: `tests/unit/test_ingest_quick_ack.py`에서 echo 이벤트가 enqueue 없이 200 OK로 끝나는지 확인합니다.
