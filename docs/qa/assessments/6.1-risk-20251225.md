# Risk Profile - Story 6.1 (2025-12-25)

## 전체 판단

- **리스크 수준**: 중간(Medium)
- 이유: Telegram/로그는 운영자가 바로 보는 곳이라, 개인정보(PII)가 새면 영향이 큽니다. 대신 마스킹을 코드에서 한 번 더 적용하고, 테스트로 막고 있습니다.

## 주요 리스크와 확인 결과

1. **SEC-001: Telegram 알림으로 PII가 새는 위험**
   - 상황: 질문에는 전화번호/이메일/카드번호 같은 PII가 들어올 수 있습니다.
   - 영향: 운영 채널에 PII가 노출되면 보안 사고가 됩니다.
   - 확인/조치:
     - `format_alert_message()`에서 `mask_user_id()`/`mask_question()`로 최종 마스킹(마지막 방어선)을 합니다.
     - 유닛 테스트로 전화번호/이메일/카드번호 마스킹을 확인했습니다.

2. **OPS-001: 조합(aggregation) 메시지 추적이 어려워지는 위험**
   - 상황: 조합 메시지인데도 Telegram/로그에 `aggregation_id`/`message_count`가 `-`/`1`로만 찍히면, 운영자가 원인을 찾기 어렵습니다.
   - 영향: “같은 사용자의 여러 메시지”가 합쳐진 건지 판단이 늦어질 수 있습니다.
   - 확인/조치:
     - `aggregator.finalize_aggregation()` → `pipeline.process_single_message()`로 `aggregation_id`/`message_count`가 전달되도록 보완했습니다.
     - 유닛 테스트(`test_worker_aggregation.py`)로 이 전달을 검증했습니다.

3. **REL-001: Telegram Markdown 포맷 깨짐(낮음)**
   - 상황: `parse_mode=Markdown`라서, 질문/초안에 특수문자(`_`, `*` 등)가 많으면 메시지 모양이 깨질 수 있습니다.
   - 영향: 메시지는 보내지지만 읽기 어려울 수 있습니다.
   - 제안(선택): Markdown escape 규칙을 정하거나, `parse_mode=HTML`로 바꾸고 escape 규칙을 정하세요.
