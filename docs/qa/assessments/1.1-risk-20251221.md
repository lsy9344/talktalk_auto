# Risk Profile - Story 1.1 (2025-12-21)

## 전체 판단

- **리스크 수준**: 낮음 (Low)
- 이유: 문서 정리 중심 스토리이며, 고객/운영 정책과 외부 제약사항이 문서로 명확히 남았습니다.

## 확인한 리스크와 대응

1. **정책이 구현에서 빠질 위험**
   - 설명: "무응답"/"금지 응답"/"Telegram 알림" 규칙이 실제 코드에서 누락될 수 있습니다.
   - 대응: Worker Lambda 구현 시, 정책을 테스트(금지 문구 검사/무응답 흐름)로 고정합니다.

2. **Naver 톡톡 웹훅 타임아웃 대응 누락 위험**
   - 설명: 3s/5s 제약 때문에 즉시 200 OK + 비동기(SQS)가 필수입니다.
   - 대응: Ingest는 최소 작업만 하고, Worker에서 무거운 작업을 합니다.

3. **문서가 시간이 지나며 오래될 위험**
   - 설명: 실제 구현이 진행되면 문서와 코드가 달라질 수 있습니다.
   - 대응: 큰 설계 변경이 생기면 `docs/architecture.md`와 PRD Epic 문서를 함께 갱신합니다.
