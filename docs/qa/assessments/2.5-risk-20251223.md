# Risk Profile - Story 2.5 (2025-12-23)

## 전체 판단

- **리스크 수준**: 중간(Medium) → SQS Delay + DynamoDB 상태 + Worker 분기(만료/중복)가 섞여 있어, 작은 실수도 장애로 이어질 수 있습니다.
- 다만 QA 리뷰에서 발견된 런타임 버그/PII 로그 위험은 수정했고, 유닛 테스트로 보호되어 리스크를 낮췄습니다.

## 주요 리스크와 확인 결과

1. **Worker 메시지 포맷 불일치로 런타임 오류 위험**
   - 발견: `Worker(app.py)`가 `Aggregator(handle_aggregation)`를 잘못 호출할 수 있었습니다.
   - 조치: `handle_aggregation(channel_id, webhook_event)`로 정리 + 유닛 테스트 추가.

2. **타임 윈도우(30초) 이후 늦은 메시지 처리 위험**
   - 요구사항(AC7): 만료 후 추가 메시지는 **새 집계 세션**을 시작해야 합니다.
   - 조치: `expires_at` 기준으로 만료를 판단하고, 만료면 새 집계를 시작하도록 수정했습니다.

3. **중복/늦은 트리거로 이중 처리 위험**
   - 확인: finalize 시 `status != AGGREGATING`이면 즉시 무시합니다.
   - 테스트: “이미 완료된 상태면 스킵” 유닛 테스트가 있습니다.

4. **PII 로그 노출 위험(user_id, 질문 원문)**
   - 발견: `user_key`(user_id 포함) / 합친 질문 텍스트가 로그에 찍힐 수 있었습니다.
   - 조치: `mask_user_id`, `mask_question`로 마스킹 로그를 적용했습니다.
