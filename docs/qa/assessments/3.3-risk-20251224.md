# Risk Profile - Story 3.3 (2025-12-24)

## 전체 판단

- **리스크 수준**: 낮음~중간(Low/Medium)
- 이유: 청킹 규칙이 바뀌면 검색 품질/비용에 영향을 줄 수 있고, tokens를 “근사”로 계산하기 때문에 실제 문서(특히 한국어)에서 차이가 날 수 있습니다.
- 다만 유닛/통합 테스트가 있고, `pytest/ruff/mypy(src)`로 검증되어 기본 안정성은 좋습니다.

## 주요 리스크와 확인 결과

1. **OPS-001: 토큰 근사 오차로 청크가 너무 커질 위험**
   - 상황: 현재 tokens를 `문자 수 / 4`로 근사합니다.
   - 영향: 한국어 문서에서 실제 토큰 수가 더 많을 수 있어, 생각보다 큰 청크가 생길 수 있습니다.
   - 권장: 운영에서 청크 길이/임베딩 비용을 보고 필요하면 실제 tokenizer 옵션을 검토하세요.

2. **REL-001: 벡터 순서와 청크 메타데이터 순서가 어긋날 위험(낮음)**
   - 확인: 현재 구현에서는 모든 청크가 텍스트를 가지며, embeddings 리스트와 chunks 리스트가 같은 순서를 유지합니다.
   - 권장: 안전을 위해 “빈 텍스트 청크가 없도록” assert/필터를 추가하면 더 좋습니다(선택).

3. **TEST-001: chunk_sections 크기 범위 테스트가 간접적(낮음)**
   - 확인: `chunk_text()`에서 토큰 근사 범위를 테스트합니다.
   - 권장: `chunk_sections()`도 크기 범위를 직접 테스트하면 더 명확합니다(선택).
